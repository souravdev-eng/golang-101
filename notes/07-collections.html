Arrays and slices

This folder shows Go's two kinds of ordered list: the fixed-size array and the flexible slice. Slices are the one you'll use nearly all the time. The key idea is that a slice is a view onto an array that sits underneath it.

What this folder is for

A JS array does everything. Go splits that job in two. An array has a length fixed as part of its type. A slice is a small description (start, length, capacity) of part of an array, and it can grow with append (Go blog: Slices intro).

JS/TS you know

const fruits = ["apple", "banana"];
fruits.push("pear");
const part = fruits.slice(0, 2); // a copy
fruits.length;

Go equivalent

fruits := []string{"apple", "banana"}
fruits = append(fruits, "pear")
part := fruits[0:2] // shares memory!
len(fruits)

Watch the comments. JS .slice() copies, but Go's fruits[0:2] shares the same underlying elements.

Key ideas

[3]int{…}
An array. The number in brackets is part of the type, so [3]int and [4]int are different types. Assigning an array to a new variable copies every element.
[]string{…}
A slice. The brackets are empty. This is Go's everyday list (Tour: Slices).
s[low:high]
Makes a new slice from index low up to, but not including, high. Leave out low to start at 0, or high to go to the end. The new slice shares elements with the original (Tour: Slices are like references).
len(s) · cap(s)
Length is how many elements you can see. Capacity is how much room the underlying array has before Go must allocate a bigger one (Tour: Length and capacity).
make([]int, 0, 3)
Creates a slice with length 0 and capacity 3.
s = append(s, x)
Adds elements and returns the updated slice. You must keep that returned value (Tour: Appending).

What to look for in each example

Run every command from the repository root.

01 · Fixed-size arrays

07-collections/01-arrays/main.go

  • [3]int{10, 20, 30} holds exactly three ints.
  • copyOfScores := scores copies the whole array. Changing the copy leaves the original alone. In JS, both names would point to the same array.
  • var empty [2]int is filled with zero values, so it prints [0 0].

Run

go run ./07-collections/01-arrays

Expect

scores: [10 20 30]
first: 10 length: 3
original: [10 20 30]
copy: [99 20 30]
zero array: [0 0]

Try: change the second element of copyOfScores and check the original.

02 · Indexing, slicing, and sharing

07-collections/02-slices/main.go

  • fruits[1:3] gives indexes 1 and 2: [banana pear].
  • middle[0] = "orange" changes fruits too. Both slices look at the same array. This is the big surprise of this folder.
  • fruits[:2] and fruits[2:] show the shorthand forms.

Run

go run ./07-collections/02-slices

Expect

first: apple length: 4
middle: [banana pear]
fruits: [apple orange pear plum]
first two: [apple orange]
last two: [pear plum]

Try: change the bounds to fruits[2:4] and predict which fruit changes.

03 · Append, length, and capacity

07-collections/03-append-capacity/main.go

  • Follow the two numbers len and cap line by line: 0/3, then 2/3, then full at 3/3.
  • Every call is written scores = append(scores, …). The result goes back into the variable.
  • Appending the 4th value goes past capacity, so Go allocates a bigger array. The code prints only the length here, because the new capacity is chosen by Go and you shouldn't rely on it.

Run

go run ./07-collections/03-append-capacity

Expect

start: 0 3
scores: [10 20]
length/capacity: 2 3
full: [10 20 30]
grown: [10 20 30 40] length: 4

Try: append 50 as well and predict the final length.

Gotchas coming from JS/TS

  • Reading past the end, for example fruits[10], doesn't give undefined. When the index is only known at run time, the program panics (crashes) (spec: Index expressions).
  • append(s, x) on its own line, without s =, doesn't compile. The compiler complains that the result isn't used.
  • Sub-slices share memory. When you need an independent copy, use copy(dst, src) or build a new slice (Go blog).

Check yourself

a := []int{1, 2, 3}, b := a[0:2], then b[0] = 9. What does a print?

Slicing doesn't copy. b is a view of the first two elements of the same array, so writing through b changes a.

s := make([]int, 0, 3). What are len(s) and cap(s)?

The second argument to make is the length (0 visible elements). The third is the capacity (room for 3).

In short

  1. Arrays have a fixed length and are copied when assigned. You'll rarely use them directly.
  2. Slices are views onto an array. Slicing shares memory, it doesn't copy.
  3. Always write s = append(s, …). len is what you see, cap is the room left.
