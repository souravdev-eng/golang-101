Strings, bytes, and runes

This folder shows what a Go string really is: a read-only sequence of bytes, usually holding UTF-8 text. You'll see why len("café") is 5, and how to work with whole characters (runes) instead.

What this folder is for

In JS, a string is a sequence of UTF-16 code units, and "café".length is 4. In Go, a string is a sequence of bytes, and é takes two of them in UTF-8 (Go blog: Strings, bytes, runes and characters). Once you know that, the behaviour in this folder makes sense.

JS/TS you know

const word = "café";
word.length;        // 4
word[0];            // "c" (a string)
[...word].length;   // 4 code points

Go equivalent

word := "café"
len(word)           // 5 bytes
word[0]             // 99 (a byte)
len([]rune(word))   // 4 runes

Key ideas

string
Read-only bytes. You can't change a string in place. You build a new one instead (spec: String types).
byte
Another name for uint8, a number from 0 to 255. len(s) counts bytes, and s[i] gives a byte.
rune
Another name for int32. It holds one Unicode code point, such as é (Go blog).
'H'
Single quotes make a rune literal, one character. Double quotes make a string.
for i, r := range s
Decodes the string one rune at a time. i is the byte offset where that rune starts, not a character count (spec: For range).
[]byte(s) · []rune(s) · string(x)
Conversions. They make an editable copy of the text, and string(x) turns it back into a string.

What to look for in each example

Run every command from the repository root.

01 · Bytes and runes

09-text/01-bytes-runes/main.go

  • len(word) is 5, not 4, because é takes 2 bytes.
  • word[0] prints 99, the byte value of c, not the letter.
  • In the range loop the offsets go 0, 1, 2, 3. If there were a character after é, its offset would be 5, because é covers bytes 3–4.
  • %c prints a rune as a character.

Run

go run ./09-text/01-bytes-runes

Expect

bytes: 5
first byte: 99
runes: 4
byte 0: c
byte 1: a
byte 2: f
byte 3: é

Try: set word := "éa" and predict the byte offset of a.

02 · Editing copies of text

09-text/02-text-copies/main.go

  • []byte(greeting) makes an editable copy. After the edit, greeting is still hello.
  • For non-ASCII text, edit a []rune so you replace whole characters. Here word[3] is the whole é.
  • + joins strings, just as in JS.

Run

go run ./09-text/02-text-copies

Expect

original: hello
edited: Hello
rune edit: cafs
joined: Hello Go

Try: set the final rune back to 'é' and compare the result.

Gotchas coming from JS/TS

  • s[i] is a number (a byte), not a one-letter string. Printing it shows a number like 99.
  • len(s) counts bytes. To count characters, use len([]rune(s)) or utf8.RuneCountInString(s) (unicode/utf8).
  • s[0] = 'H' doesn't compile, because strings are read-only. Convert to []byte or []rune, edit, then convert back.

Check yourself

What does len("café") return in Go?

len on a string counts bytes. In UTF-8, c, a and f take 1 byte each and é takes 2, so the total is 5.

In for i, r := range "éa", what is i when r is 'a'?

range gives the byte offset where each rune starts. é covers bytes 0–1, so a starts at byte 2.

In short

  1. A string is read-only bytes (UTF-8). len and s[i] work on bytes.
  2. A rune is one Unicode code point. range over a string gives runes along with their byte offsets.
  3. To edit text, convert to []byte or []rune (a copy), then back with string(…).
