Functions and scope

This folder shows how Go functions take inputs, give back one or more results, accept any number of arguments, and live in variables. It ends with scope: which variable a name refers to inside a block.

What this folder is for

Functions in Go feel close to JS functions. The main difference is types. Every parameter and every result has a declared type, and it's written after the name (Tour: Functions).

JS/TS you know

function total(price: number,
               quantity: number): number {
  return price * quantity;
}
const cost = total(3, 4);

Go equivalent

func total(price int, quantity int) int {
    return price * quantity
}

cost := total(3, 4)

In both versions the return type comes after the parameter list. Go has no colons and no function keyword, only func.

Key ideas

func name(p T) R
A parameter is a name followed by its type. The type after the ) is the result type. Leave it out when the function returns nothing.
a, b int
When neighbouring parameters share a type, you can write the type once (Tour: Functions continued).
(int, int)
A function can return several results. The caller receives them in the same order: each, left := f() (Tour: Multiple results). Unlike JS, you don't wrap them in an array or object.
...int
A variadic parameter takes zero or more values. Inside the function it's a slice, []int (spec). It works like JS rest parameters ...nums.
func(x int) int { … }
A function with no name, an anonymous function. It's a value you can store in a variable and call later, just like an arrow function (Tour: Function values).
block scope
A variable exists from its declaration to the end of the nearest { } (spec: Declarations and scope). That's the same as let in JS.

02 · Multiple return values

06-functions/02-multiple-returns/main.go

  • The signature (apples, people int) (int, int) takes two ints and returns two ints.
  • return a, b sends back both results. each, left := … receives them in order.
  • / on ints drops the remainder and % gives the remainder, so 7 split among 3 gives 2 each with 1 left over.
  • This pattern matters later: Go functions usually report errors as an extra return value (Topic 13).

Run

go run ./06-functions/02-multiple-returns

Expect

each: 2 left: 1

Try: split 10 apples among 4 people. Predict both numbers first.

03 · Variadic and anonymous functions

06-functions/03-variadic-anonymous/main.go

  • sum(numbers ...int) loops over numbers with range, because inside the function it's a slice.
  • sum() with no arguments is allowed. The slice is empty, so the total stays 0.
  • double := func(number int) int { … } stores a function in a variable. You call it with double(5).

Run

go run ./06-functions/03-variadic-anonymous

Expect

sum: 9
empty sum: 0
double: 10

Try: pass an extra value to sum and predict the result.

04 · Scope and shadowing

06-functions/04-scope/main.go

  • Inside the first if, message := "inside" creates a new variable with the same name. This is called shadowing. The outer one isn't touched.
  • Inside the second if, message = "updated" uses plain =, so it changes the outer variable.
  • That one character, := versus =, is the whole lesson.

Run

go run ./06-functions/04-scope

Expect

outside
inside
outside
updated

Try: change the first inner := to =. Predict which lines change.

Gotchas coming from JS/TS

  • Go has no default parameter values and no function overloading (Go FAQ). Every call passes every argument.
  • Accidental shadowing with := inside an if or for is a classic Go bug. The code compiles, but the outer variable never changes.
  • If you don't need one of several results, you can't just ignore it. Receive it into the blank identifier _, for example _, left := splitApples(7, 3) (Effective Go: the blank identifier).

Check yourself

Inside func sum(numbers ...int), what type is numbers?

A variadic parameter ...T is seen as a []T inside the function. That's why sum can use range on it.

x := 1, then inside if true { x := 2 }. What is x after the if?

:= inside the block declares a new x that disappears at the closing brace. The outer x is still 1. Redeclaring is only an error when it's in the same block.

In short

  1. Types come after names: func f(a, b int) (int, int).
  2. Multiple results are received in order. Use _ to skip one you don't need.
  3. ...T is a slice inside the function. Anonymous functions are values.
  4. := in an inner block makes a new variable. = changes the existing one.
