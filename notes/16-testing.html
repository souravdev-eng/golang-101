Testing

This folder pairs a tiny function with its test. By the end you'll be able to find a Go project's tests, read one, and run it, all without installing a testing framework.

What this folder is for

Testing is built into Go: the testing package plus the go test command (testing package). When you join a Go project, the tests usually sit right beside the code they check. Reading them is one of the fastest ways to learn what the code is meant to do.

JS/TS you know (Jest)

// total.test.ts
test("total", () => {
  expect(total(3, 4)).toBe(12);
});

Go equivalent

// main_test.go
func TestTotal(t *testing.T) {
    got := Total(3, 4)
    want := 12
    if got != want {
        t.Fatalf("Total(3, 4) = %d; want %d", got, want)
    }
}

There's no expect. A Go test is ordinary code: compute a result, compare it with an if, and report a failure through t.

The conventions go test relies on

*_test.go
Test files end in _test.go. go test uses them; go run and go build leave them out (go command: Test packages).
func TestXxx(t *testing.T)
Each test is a function whose name starts with Test and that takes a *testing.T.
got / want
A common naming habit: got is what the code returned, want is the expected answer.
t.Errorf · t.Fatalf
Both mark the test as failed and print a message. Errorf lets the test keep going. Fatalf stops this test right there.
Same package
Here the test file also says package main, so it can call Total directly.

What to look for in each example

Run every command from the repository root, the folder that contains go.mod.

01 · Total and its test

16-testing/01-total/main.go + main_test.go

  • In main.go: Total is a plain function, and main only calls it and prints the result.
  • In main_test.go: the test calls Total just like any other caller would. No mocks, no framework.
  • The failure message shows both values, so a failing run tells you what went wrong.

Run the program

go run ./16-testing/01-total

Expect

cost: 12

Run the test

go test ./16-testing/01-total -run '^TestTotal$' -v

Expect (timings and the package line vary)

--- PASS: TestTotal (0.00s)
PASS
ok  	github.com/sauravdev-eng/16-testing/01-total	…

Try: change want to 13 and run the test again. Read the failure message, then put 12 back.

go test flags worth knowing

go test ./...
Runs the tests in every package of the module. Packages without tests show [no test files].
-v
Verbose: prints each test's name and result, not just the package summary.
-run 'regex'
Runs only the tests whose names match the pattern.
(cached)
If nothing has changed, Go may reuse the last result and print (cached) (go command docs).

Gotchas coming from JS/TS

  • There's no expect(...).toBe(...) built in. The comparison is a plain if, and t.Errorf/t.Fatalf do the reporting.
  • The name has to be Test followed by an uppercase letter (or nothing). testTotal or CheckTotal is silently skipped.
  • Tests live in the same folder as the code, not in a separate __tests__ directory.

Check yourself

Which function will go test run as a test?

Test functions must be named Test followed by a capitalised name, and must take *testing.T.

What is the difference between t.Errorf and t.Fatalf?

Both mark the test as failed. Fatalf also stops the current test straight away (testing: T.Fatalf). Other tests still run.

In short

  1. Tests sit in *_test.go files next to the code, as func TestXxx(t *testing.T).
  2. Compare got with want using an if; report with t.Errorf or t.Fatalf.
  3. Run them with go test ./..., adding -v and -run to focus.
