Why context exists

Before the solution, feel the problem. This folder has no context at all — it shows the exact pain the next thirteen notes remove: work that can't hear you say "stop".

The idea

A goroutine is started to count up to 5. After step 1, imagine the caller no longer cares about the result. There is nothing it can do. The worker has no input that means "stop early", so it runs every step and the caller just waits for all of it. That missing stop signal is the one thing context adds.

The code that matters

func countUp(steps int, workers *sync.WaitGroup) {
    defer workers.Done()
    for step := 1; step <= steps; step++ {
        fmt.Println("worker: step", step)
        // Notice: no check for "should I stop?". There is no way to.
    }
}

go countUp(5, &workers)
workers.Wait() // The only option is to wait for ALL of it.

Hold this feeling. Every later note is really answering: how would the worker know to quit here?

Run it

18-context/01-why-context/main.go

Run

go run ./18-context/01-why-context

Expect

worker: step 1
worker: step 2
worker: step 3
worker: step 4
worker: step 5
main: the worker ran all 5 steps; I had no way to stop it

Try: change countUp(5, ...) to countUp(8, ...). Predict how many worker: step lines print before the final line.

Check yourself

What is this example missing that the rest of the section adds?

The work starts and counts fine. What it can't do is stop early — there's no signal to listen for. That signal is context.

In short

Context exists so running work can be told to stop. Next you'll meet the empty root every context is built from.
