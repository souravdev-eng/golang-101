Maps

This folder shows Go's key–value store, the map. You'll look up, insert, update and delete keys. You'll also learn to tell "missing" apart from "zero", and why map output needs sorting.

What this folder is for

A Go map works like a JS Map, or an object used as a dictionary. The difference is that every key has the same type and every value has the same type, and both are written into the map's type (Go blog: Go maps in action).

JS/TS you know

const stock = new Map<string, number>(
  [["apples", 3]]);
stock.set("pears", 2);
stock.get("kiwi");   // undefined
stock.has("kiwi");   // false
stock.delete("pears");

Go equivalent

stock := map[string]int{"apples": 3}
stock["pears"] = 2
stock["kiwi"]            // 0 (zero value)
_, ok := stock["kiwi"]   // ok == false
delete(stock, "pears")

Key ideas

map[string]int
A map from string keys to int values. You can create one with a literal {…} or with make(map[string]int).
m[key] = v
The same syntax inserts a new key or updates an existing one.
m[key]
Reading a missing key doesn't fail. It returns the value type's zero value, so 0 for int (Go blog).
v, ok := m[key]
The "comma ok" form. ok is true only when the key is really there (Tour: Mutating maps).
delete(m, key) · len(m)
Removes a key (deleting one that isn't there is fine), and counts the keys.
for k := range m
Visits every key. The order is not specified and can change from run to run (spec: For statements with range).

Gotchas coming from JS/TS

  • A map declared with only var m map[string]int is nil. Reading it works, but writing to it panics. Create it with make or a literal first (Go blog).
  • Don't use m[key] == 0 to test whether a key exists. Use _, ok := m[key].
  • JS Map keeps insertion order. Go maps don't keep any order, so sort the keys whenever the order matters.

Check yourself

m := map[string]int{}. What does fmt.Println(m["kiwi"]) do?

A missing key returns the value type's zero value. For int that's 0. Use v, ok := to find out whether the key was there.

You range over a map and print each key. What order do the keys come in?

The language spec leaves map iteration order unspecified. Collect the keys, sort them, then loop over them.

In short

  1. map[K]V, where m[k] = v inserts or updates, and delete(m, k) removes.
  2. Missing keys give the zero value. v, ok := m[k] tells you whether the key exists.
  3. Iteration order is random, so sort the keys for stable output. Write only to maps made with make or a literal.
