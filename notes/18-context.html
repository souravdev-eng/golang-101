The context package

This folder has fourteen runnable sub-topics. This page is the map: the one idea they all share, and a reading path through them. Each sub-topic has its own short note — read one, run its folder, then come back here for the next.

The one idea, in one picture

Every function doing real work keeps asking the same question: "should I still be doing this?" A context.Context is the thing it asks. The answer is a channel, ctx.Done(), that stays open (keep going) until someone closes it (stop now). That's the whole package.

JS/TS you know

const controller = new AbortController();
const { signal } = controller;

fetch(url, { signal });      // pass it down
controller.abort();          // signal "stop"
signal.aborted;              // true now

Go equivalent

ctx, cancel := context.WithCancel(
    context.Background())

doWork(ctx)   // pass it down
cancel()      // signal "stop"
ctx.Err()     // context.Canceled now

If you've used AbortController / AbortSignal with fetch, you already understand context. Go's version does three extra things JS doesn't: it can cancel itself after a timeout or at a deadline, it forms a parent/child tree (cancel a parent and every child cancels too), and it can carry a few request-scoped values along for the ride (Go blog: Context).
