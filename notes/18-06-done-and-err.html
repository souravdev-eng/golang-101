Reading Done and Err

You've made contexts stop three ways. This note ties the knot: Done() tells you that work stopped; Err() tells you why. Together they're the entire listening side of context.

The idea

<-ctx.Done()
Blocks until the context finishes. It's a channel, so you receive from it (usually inside a select). It carries no value — the close is the signal.
ctx.Err()
After Done() fires, returns the reason. Exactly two values matter: context.Canceled (someone called cancel()) and context.DeadlineExceeded (a timeout or deadline passed).

So the pattern is always: wait on Done(), then check Err() to branch on the reason. A switch on ctx.Err() reads cleanly.

The code that matters

func describe(ctx context.Context, label string) {
    <-ctx.Done() // wait until it's over
    switch ctx.Err() {          // then ask why
    case context.Canceled:
        fmt.Println(label, "was cancelled by a caller")
    case context.DeadlineExceeded:
        fmt.Println(label, "ran out of time")
    }
}

// Case 1 — explicit cancel -> context.Canceled
ctx1, cancel1 := context.WithCancel(context.Background())
cancel1(); describe(ctx1, "manual:")

// Case 2 — timeout -> context.DeadlineExceeded
ctx2, cancel2 := context.WithTimeout(context.Background(), 10*time.Millisecond)
defer cancel2(); describe(ctx2, "timeout:")

Check yourself

A timeout fired. What does ctx.Err() return?

Canceled comes from an explicit cancel(); a timeout or deadline gives DeadlineExceeded. Err() is nil only before Done() fires.
